# gbird

**The org's agent trace store.** One place where every teammate's agent sessions land — captured by a lifecycle hook, stored as plain JSON files, browsable in a small UI, readable over a JSON API.

```
agent fires event (prompt, tool call, session end)
  → ~/.gbird/gbird-hook.mjs record     appends to local live/<session>.jsonl
session ends
  → ~/.gbird/gbird-hook.mjs ship       assembles the trace → POSTs it to the server
the server                              POST /v1/traces → sessions/<agent>/<id>.json
                                        GET /           → traces UI
                                        GET /api/...    → programmatic access
```

## Run the server

```bash
npm install && npm run build
node dist/src/cli.js serve --port 8780      # UI + ingest API at http://localhost:8780
```

Store lives in `GBIRD_DIR` (default `~/.gbird`): `index.json` manifest + `sessions/<agent>/<id>.json` + `members.json`. No external database — the file tree is the DB, which means you can also commit it, rsync it, or move it wholesale.

## Onboard a teammate

```bash
node dist/src/cli.js invite sara
#   token:   gbird_…
#   install: http://localhost:8780/install/gbird_…
```

Send Sara the install URL. The page is **a prompt, not instructions for a human** — she hands it to her agent (Devin, Claude Code, …) and the agent downloads the hook, writes the hooks config into the right config file, and verifies a self-test trace lands. No CLI install, no accounts.

Admin-side token minting is also exposed at `POST /api/members` when `GBIRD_ADMIN_TOKEN` is set.

## The hook

`hooks/gbird-hook.mjs` is self-contained (~350 lines, node builtins only — compiled from `src/hookentry.ts`, regenerated by `npm run build`). It never throws, so a broken hook can't break the agent.

- `record` — maps one hook stdin payload (SessionStart, UserPromptSubmit, Pre/PostToolUse, PermissionRequest, Stop, PostCompaction, SessionEnd) to a normalized event and appends it to `~/.gbird/live/<agent>/<session>.jsonl`.
- `ship` — records its own stdin (so `session_ended` is captured), assembles `sessions/<agent>/<id>.json`, then POSTs it to `GBIRD_ENDPOINT` with the member's `GBIRD_TOKEN`, or falls back to `GBIRD_REPO` git-push mode, else keeps it local.
- `collect` — folds all live logs into session files on demand.

Wired events in the generated config: `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `SessionEnd`. Everything stays local-first — `live/` accumulates during the session, so a network blip loses nothing.

## API

```
POST /v1/traces                    ingest one SessionTimeline  (Bearer member token)
GET  /api/sessions?member&agent&repo&q    list sessions
GET  /api/sessions/:id             one full timeline
GET  /api/members                  members (tokens are never returned)
POST /api/members {name}           mint a token  (Bearer GBIRD_ADMIN_TOKEN)
GET  /v1/hook.mjs                  the hook runtime
GET  /v1/hooks.v1.json?token=      per-member hook config (endpoint+token baked in)
GET  /install/:token[.md]          the self-setup prompt for a teammate's agent
GET  /                             traces UI;  GET /s/:id  session detail
```

`gbird pull` remains for backfill — Devin sessions via the v3 API (`DEVIN_API_KEY`/`DEVIN_ORG_ID`, `npm run secret:save`) and Codex rollouts from `~/.codex/sessions` (Codex has no lifecycle hooks). Incremental via `updated_at` / file hash; `--force` overrides.

## Env

`GBIRD_DIR` store dir · `GBIRD_PORT`/`--port` · `GBIRD_BASE_URL`/`--base-url` public URL for install links · `GBIRD_ADMIN_TOKEN` admin API · hook side: `GBIRD_ENDPOINT`, `GBIRD_TOKEN`, `GBIRD_AGENT`, `GBIRD_REPO`

## Development

```bash
npm test
npm run build        # tsc + regenerates hooks/gbird-hook.mjs
```

`src/hookentry.ts` is deliberately self-contained (node builtins only) so its compiled output *is* the portable hook script — don't import other `src/` modules from it.

Node ≥ 22.5.
